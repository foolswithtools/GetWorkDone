# The unit partition failed on a stock Mac: bash 3.2, BSD sha256sum and a slow rollout test

Resolved in GWP#165. Seen in the local gate runs of GWP#158 (PR #164) and GWP#103 (PR #166). CI on `ubuntu-latest` was never affected.

On `main` at 571ae39, under Node 24.22.2 with the system `/bin/bash` (3.2.57) and `/sbin/sha256sum` (`sha256sum (Darwin) 1.0`), `pnpm test:unit` exited 1 with `15 failed | 1376 passed | 3 skipped (1394)`. Vitest writes no coverage summary when a test fails, so a Mac could not show one either.

- **`scripts/image-migrate-check.sh`, 8 failures.** The script reads `DATABASE_URL`'s query into an array with `IFS='&' read -r -a params` and loops over it under `set -euo pipefail`. With no query the array is empty, and bash before 4.4 aborts an unguarded expansion of an empty array with `params[@]: unbound variable`. Every accepted URL without a query failed. The loop now expands `${params[@]+"${params[@]}"}`. That form expands to nothing for an empty array on bash 3.2 and to every key, empty keys included, everywhere, so each key is still checked and every URL refused before still exits 2.
- **`tests/workflows/publish-guards.test.ts` "snapshot compare", 6 failures.** These cases run `publish.yml`'s compare step exactly as written, and the step uses `sha256sum --check --strict`, which are coreutils options. macOS's `sha256sum` prints its usage line and exits 1 for them. `publish.yml` runs only on `ubuntu-latest` and is unchanged. Instead, the describe's cases skip themselves when `sha256sum --version` names neither GNU nor uutils coreutils. The check uses the tool's own output, never the OS name, and each skipped case prints the reason. `ubuntu-latest` is ubuntu-26.04 (as of November 2026; main's CI ran on it from at least 2026-11-01), and its `sha256sum` is the Rust uutils one (`sha256sum (uutils coreutils) 0.10.0`). A check for GNU alone would have skipped all nine cases on CI, and the whole-branch review caught that before merge. Under GitHub Actions the cases never skip: if a runner's `sha256sum` is not coreutils, they fail, so CI can't lose them silently. On CI all nine cases still run.
- **`tests/scripts/check-digests-sh.test.ts` "waits through a rollout that outlasts the old two-minute budget, with the default attempts", 1 timeout.** This test is slow by construction. Each of its 20 polls starts the fake `aws` (bash, then node to record the call) and the script's `jq` calls. That takes about 4 s on a Mac when the test runs alone, and a full parallel run pushed it past vitest's 5 s default. The test now has its own 30 s timeout, with that reason in a comment. The global `testTimeout` is unchanged.

The `image-migrate` gate itself still can't run on a Mac. It needs `psql`, and its `docker run --network host` doesn't reach a Postgres published on the Mac's localhost under Docker Desktop. `README.md`'s gate list now says so. Making that gate run on macOS is out of scope.

Regression tests:

- `tests/scripts/image-migrate-check.test.ts`, "expands every array read -a fills only in the form bash 3.2 accepts under set -u". This is a source check that CI's bash 5 can run. On a Mac where `/bin/bash` is the first `bash` on PATH (`tests/scripts/fake-bin.ts` runs `bash` from PATH), the file's other cases, including "recreates image_migrate, runs the image's migrate command twice as migrate.sh writes it, then checks the result" and "accepts a local URL without a port or credentials", run the script under bash 3.2.
- `tests/workflows/publish-guards.test.ts`, "tells a coreutils sha256sum (GNU's or uutils') from another by its --version output (GWP#165)", and the skip on "snapshot compare", which fails instead under GitHub Actions.
- `tests/scripts/check-digests-sh.test.ts`, "waits through a rollout that outlasts the old two-minute budget, with the default attempts", with its explicit timeout.
