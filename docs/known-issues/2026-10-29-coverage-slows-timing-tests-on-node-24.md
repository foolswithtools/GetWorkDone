# Timing tests in contracts failed under coverage on Node 24

Resolved before merge, GWP#46. Found while running the gates on Node 24.22.2 for the move from Node 20: `pnpm test:unit` failed two timing budgets in `packages/contracts`, "an item of patterned fields with long classes validates quickly (repeated class escapes)" in `capture.test.ts` (1476 ms against 600) and the `{2400}` "worst case" in `pattern-matcher.test.ts` (1097 ms against 500).

The matcher is not slower on 24. Without coverage the first test took 232 ms on 24.22.2, 270 ms on 22.23.1 and 266 ms on 20.20.2. `pnpm test:unit` runs with V8 coverage (`vitest.config.ts`), and on 22 and 24 precise coverage slows these hot loops far more than on 20: 1182 ms on 24 and 1142 ms on 22 against 400 ms on 20, run alone on a 4-core host; the `{2400}` case went from 124 ms on 20 to 411 ms on 24. On that host the full unit run on 22.23.1 failed the first test too, though the 2026-10-28 review's unit run on 22.23.1 passed, so how close a run comes to the budget depends on the machine.

Fix: `packages/contracts/test/time-budget.ts`. A global setup in the unit config (`time-budget.setup.ts`) passes the resolved `coverage.enabled` to the tests, and `budget(ms)` multiplies a budget by 5 only while coverage is on, so `--coverage.enabled=false` keeps the plain budget. It is applied only to the two groups that went over: "long classes" and "worst case". Every other timing assertion in the two files stayed well inside its plain budget under coverage on 24 and keeps it, because those guard regressions of a few hundred ms: with the one-line group fix from `a2264d5` undone (`pattern-matcher.ts:115`), "compiles a deeply nested pattern without walking the nesting once per copy" took 227 ms against 50 ms, which a fivefold budget would have let through. The scaled budget still catches what its tests guard: with the class fix from `da39e5f` reverted, "long classes (repeated class escapes)" took 17 to 30 s under `pnpm test:unit` on 24 against its 3 s budget; "worst case" guards against backtracking, which on those inputs does not finish.

Regression tests: the timing tests themselves, `packages/contracts/test/capture.test.ts` "an item of patterned fields with long classes validates quickly" and `packages/contracts/test/pattern-matcher.test.ts` "worst case", which run under coverage on Node 24 in CI.
